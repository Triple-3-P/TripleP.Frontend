## Corrections and precedence

1. Repository instructions take precedence: npm, real backend integration, existing FSD/store structure, prefixed TypeScript names, localizable UI and deferred mobile application work.
2. Source `OPENAPI_P0.yaml` references point to the actually supplied `openapi-p0-core.yaml`. Missing `scripts/generate_openapi.py` and `scripts/validate_openapi.py` are identified as absent, not presented as runnable commands.
3. The core YAML contains 58 paths, 75 operations and 75 schemas. It omits the proposed CSRF endpoint and documented item-list filters/sort. No endpoint/schema was invented to fill those gaps.
4. Newer API prose uses RFC 9457 Problem Details and exact ETags; older nested `error` examples and generic version-conflict guidance are superseded.
5. Source reference code is not a tested application. Its store middleware, props/types, response casting, CSRF error handling and retry behavior need adaptation before implementation.
6. Product stage and permission-name disagreements are listed in [open decisions](implementation-plan.md). The import does not silently ratify a design option.

The draft API's external standards links are retained as source references. This import reviews local supplied materials and repository code; it does not claim a fresh review of those external standards or library documentation.
